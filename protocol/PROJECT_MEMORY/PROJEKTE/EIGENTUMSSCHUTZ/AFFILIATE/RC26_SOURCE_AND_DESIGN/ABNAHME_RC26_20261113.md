## Belegter Ausgangsbefund und KISS-Lösung
- Der **aktuell gebaute RC25-Quellstand** erlaubt die Eingabe einer Feed-ID bereits; eine zuvor angenommene feste 2901-Sperre existiert in der verifizierten RC25-Basis **nicht**. Alte isolierte Quellen zeigen noch andere Zustände; daher nie pauschal daraus schließen.
- Vor RC26 bestätigt die vorhandene iPN-Prüfung nur den **eingestellten** Feed. Wenn das iPN-Konto mehrere Quellen (Mock Fashion/Sport/Auto sowie Standarddatenfeed) meldet, existiert noch keine aktuelle, abgesicherte automatische Quellenwahl.
- RC26 verwendet **ausschließlich die vorhandene** authentifizierte iPN-`findFeeds`-API für die echte Hab-Werbefläche 568944. Die vorhandene WordPress-Option speichert nur Feed-ID, Feedname, Produktzahl und Test-Kennzeichen; keinen neuen Schlüssel oder geheime Downloadadresse. Die tatsächlichen Namen/Zahlen können **nur bei API-Prüfung im Live-Backend** festgestellt werden.
- Genau **ein** als Standarddatenfeed benannter Nicht-Test-Feed wird automatisch ausgewählt. Ist die Auswahl nicht eindeutig, wird ein bereits verifizierter Nicht-Test-Feed beibehalten, andernfalls sicher blockiert. Mock-/Testfeeds dürfen nicht produktiv importiert werden.
- Beim Wechsel auf eine neue Feed-ID: Der alte erfolgreiche Import verliert seine **öffentliche Gültigkeit** bis zum nächsten realen Import. Keine doppelten Tabellen, keine neue Engine. Nach erneutem Import gelten die bestehenden RC24-/RC25-GTIN-, Bild- und Zielprüfungen weiterhin.
- Originale manuelle iPN-Downloadadressen bleiben nur erhalten, wenn die Adresse die **exakt ausgewählte** Feed-ID (und keine fremde Adspace) bezeichnet. Andere alte Links werden beim Import ignoriert.
- Auf der bestehenden idealo-Fachseite werden die vom iPN gemeldeten Feeds mit Name, Größe und Status **„TEST – ausgeschlossen“ / „PRODUKTIV GEWÄHLT“** sichtbar. Kein erfundener Gesamt-Idealo-Bestand und kein paralleler Mock-Mischimport.
