## Nachgewiesener RC26-Fehler und KISS-Korrektur
- RC26 überschreibt eine explizit verifizierte Feed-Auswahl beim API-Test bedingungslos, sobald genau ein Feed *Standard Datafeed* heißt (`if count($standards) === 1`), selbst wenn dieser laut API 0 Produkte hat.
- RC27 **bewahrt die aktuell bestätigte ausgewählte Quelle**, sofern sie kein Mock/Test ist. Beim bewussten Wechsel auf eine andere in der bereits vorhandenen iPN-API-Feedliste verifizierte Nicht-Testquelle wird die Wahl nicht mehr durch den Namen Standard überschrieben.
- Nur wenn keine gültige Quelle ausgewählt ist, darf ein eindeutig erkannter Standardfeed mit einer **positiven** API-Produktanzahl vorgeschlagen werden. Bei fehlender Eindeutigkeit Fehler statt Vermutung.
- Im bereits bestehenden Backend-Formular wird die Feed-ID als Liste der tatsächlich verifizierten Quellen angeboten; die automatische Auswahl erfindet nichts. Keine zusätzlichen Tabellen, Worker, Feed-Schnittstellen oder Fremdportaländerungen.
- Im vorhandenen iPN-Bericht sind die Unterschiede **„laut Partner-API“**, „letzter wirklicher Import“ und unbekannte ältere Feedherkunft erklärt.
- Die öffentliche Ausgabe/Design/Produktzuordnung bleibt unverändert gegenüber RC26.
