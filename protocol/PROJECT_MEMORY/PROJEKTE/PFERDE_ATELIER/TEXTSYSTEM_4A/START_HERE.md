## KERNIDEE

Ein Artikel besitzt vom Eingang bis zum Ausgang genau einen kanonischen Zustand. Genau ein Produktionscontroller darf diesen Zustand fortschalten. Codex arbeitet fachlich, darf aber weder Route noch nächsten Schritt bestimmen. Prüfer sind reine Messinstrumente und liefern PASS oder konkrete Findings.

Zielkette:

`Produktionsanstoß/Metadaten -> Artikelzustand -> Recherche -> Fakten/Fact-Pack -> Text -> echte Vollprüfung -> Same-Article-Repair -> artikelübergreifende Prüfung -> SYSTEM4_WORDPRESS_HANDOFF_V1.json -> Elternchat -> WordPress-Entwurf`

## HARTE GRENZEN

1. **Keine Außensteuerung.** Metadaten dürfen keine Route, Regeln, Prompts, Toolchain, Publish- oder Next-State-Angaben enthalten.
2. **Eine Zustandsautorität.** Nur der Produktionscontroller darf Phasen verändern.
3. **Keine Prüf-Simulation.** Echte bestehende Prüfer bleiben alleinige PASS-Autorität.
4. **Inhalt READ-ONLY-Regelbestand.** Keine neue Autoren-/Textregel.
5. **Design READ-ONLY.** Kein Restyling und keine nachträgliche Designreparatur.
6. **Qualität unverändert.** Bestehende Fach-/SEO-/PPM-/LT-/PSERC-/PSTE-Regeln bleiben verbindlich.
7. **Flexibel.** Weder Stückzahl noch Beitragsart werden im Produktionscontroller fachlich hardcodiert.
8. **Kein Auto-Publish.** `publish_allowed=false` bleibt unveränderlich.
9. **Ein finaler Ausgang.** Nach finalem PASS existiert genau ein kanonischer WordPress-Handoff.

## ABGRENZUNG ZU SYSTEM 4

Die feste 7er-/`Beratung`-Bindung ist ein separat zu behebender Implementierungsfehler und kein 4a-Argument.

Die kritische Prüfung zeigt vielmehr: Der System-4-Kern ist bereits sehr nah am Ziel. Der echte Härtungspunkt sind noch technisch erreichbare Parallelpfade im Controller, obwohl der Zielvertrag nur den FULL-Production-/Direct-Import-Weg zulässt.

Deshalb wird aktuell **kein eigenständiger 4a-Controller** gebaut. Konzept 4 wird gegen diesen Maßstab bereinigt.

## ERFOLGSKRITERIUM

Konzept 4 ist architektonisch ausreichend, wenn nach Bereinigung gilt:
- eine technisch erreichbare Produktionsstraße;
- ein kanonischer Artikelzustand je Artikel;
- eine Workflow-Autorität;
- null Außenfreiheit für Routing;
- unveränderte Inhalte, Design- und Qualitätsautoritäten;
- komplette Automatisierung vom gebundenen Anstoß bis zur finalen Datei;
- neue freigegebene Beitragsarten ohne Controller-Umbau.

Nur wenn danach ein irreduzibler struktureller Nachteil verbleibt, darf ein eigenständiges 4a erneut erwogen werden.
